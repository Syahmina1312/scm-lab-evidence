# Session 2 Reflection

Q1. How do Issues and pull requests together support change control?

Participates in discussions on issues by stating why something has changed and what should be done. The changes can be reviewed before they are merged into the main branch by using pull requests. They offer a transparent history of the shift from request to completion.

Q2. Why did the conflict in Part 4 happen, and how could a team reduce 
such conflicts?

The conflict occurred because both branch-a and branch-b changed the same line in the `conflict-demo.md` file. The version of the code that was written was not clear to Git. A team can avoid conflicts by communicating, coordinating changes and merging branches regularly.

Q3. What would be lost if people merged straight into main without a pull request?

The team would miss the chance to look at changes prior to the merge. There also wouldn't be as much discussion, feedback and visibility of proposed changes. Pull requests give a history of the changes made and keep code quality high.
